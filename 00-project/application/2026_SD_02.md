# Board-Game Rules Companion with Source References

## My interpretation of the brief
The project aims to build a mobile-friendly web application that helps players resolve situational board-game rule questions using a Retrieval-Augmented Generation (RAG) pipeline. Rather than providing general LLM responses, the system must retrieve precise text excerpts from official rulebooks, cite section and page numbers, and explicitly handle ambiguous or insufficient rule contexts. Key challenges include managing document hierarchies across game editions and expansions, ensuring stable reference mapping, and allowing users to verify LLM answers against original source excerpts.

## Proposed approach
Architecture & Stack: Separate the core retrieval/AI pipeline, web application backend, and responsive frontend UI into clean modules.   Document Processing Pipeline: Parse text-based PDFs or Markdown rulebooks into structured hierarchical chunks preserving game, edition, section, and page metadata.   Hybrid Retrieval Strategy: Combine keyword-based candidate generation with vector semantic search, using cross-references and section hierarchies for reranking.   LLM Integration & Citations: Prompt the LLM strictly with retrieved contexts to formulate precise answers, cite exact references, or explicitly state when information is insufficient.   Evaluation System: Build a test dataset of situational queries to systematically measure recall, citation accuracy, latency, and handling of unanswerable cases.   

## Initial plan
Phase 1 (Weeks 1–3): Requirements refinement, database scheme design (documents, editions, rules), and setting up document ingestion/parsing scripts.Phase 2 (Weeks 4–6): Implementation of hybrid search (keyword + semantic embeddings) and section cross-referencing logic.   Phase 3 (Weeks 7–9): Backend integration with LLM API, establishing strict grounding/citation prompts, and creating user clarification flows.   Phase 4 (Weeks 10–11): Development of the mobile-friendly web UI for rule browsing, query entry, reference inspection, and feedback logging.   Phase 5 (Weeks 12–14): Evaluation on test datasets, tuning retrieval parameters, writing automated integration tests, and finalizing documentation.
